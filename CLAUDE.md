# CLAUDE.md

Guidance for AI coding sessions working on this repository.

## What this project is

Computer Font is an OFL-licensed, parametric, code-drawn variable font inspired by a 1992 blocky "computer" display face ("Computerfont" on dafont, author and license unknown). Glyphs are generated by Python in `src/computerfont/` as UFO masters, then compiled with fontmake into a variable TTF and WOFF2. Axes: `wght` 200–900 (default 400) and `ROND` 0–100 (corner radius, default 0). v0.1 charset is printable ASCII only (U+0020–007E) plus `.notdef`. We never copy outlines from the original font; it is a visual reference only.

Status: v0.1.0 content is complete (all 95 ASCII glyphs, spacing, basic kerning, CI). No release tag has been pushed yet. The public repo is `areimel/computer-font`.

## Commands

```sh
make setup     # venv + requirements.txt + editable install
make build     # python -m computerfont.build --static  (UFOs -> fonts/variable/ TTF + WOFF2, fonts/static/ 12 TTFs)
make test      # python -m pytest -q
make proof     # python -m computerfont.proof (grid + waterfall PNGs in proofs/)
make reference # bash scripts/fetch_reference.sh (gitignored reference/)
make clean     # remove build/ fonts/ sources/generated/ proofs/
```

The Makefile sets `PYTHONPATH=src`. Outside make, prefix commands with it:

```sh
PYTHONPATH=src .venv/bin/python -m computerfont.build                   # variable font only (faster iteration)
PYTHONPATH=src .venv/bin/python -m computerfont.proof --readme          # docs/images/specimen.png (README banner)
PYTHONPATH=src .venv/bin/python scripts/render_glyphs.py "ABC" out.png  # per-master glyph preview, no fontmake
PYTHONPATH=src .venv/bin/python scripts/render_glyphs.py --all out.png  # every glyph
```

Before committing glyph or engine changes, run **both** `make test` and `make build`. Tests check our own point structure, but only fontmake's compatibility check proves the masters interpolate.

## Architecture map

All code lives in `src/computerfont/`:

- `config.py`: the single source of metric values. `FAMILY_NAME`, UPM 1000, cap height 700, x-height 540, ascender 760, descender -220, `STEM_CONTRAST`, axis ranges, masters, named instances, and `Params.at(wght, rond)`.
- `geometry.py`: `Pt`, `Contour` (translate, mirror, flip, counter, orientation), `rect`, `polygon`, `Turtle`, `notch_corners`.
- `corners.py`: compatible corner rounding. Every vertex becomes 4 points (on, off, off, on). At radius 0 the handles collapse onto the corner.
- `components.py`: reusable Params-driven shapes. This is the DRY core (API below).
- `registry.py`: the `@glyph(name, unicode, width=...)` decorator, `all_glyphs()`, and `get()`.
- `glyphs/`: `basic.py` (.notdef, space), `uppercase.py`, `uppercase_diag.py` (K N V X Y Z), `lowercase.py`, `digits.py`, `punctuation.py`, `symbols.py`. Glyph files only compose parts. `glyphs/README.md` explains how to add a glyph.
- `spacing.py`: per-group target sidebearings (multiples of `p.sb`) and `space_width(p)`.
- `kerning.py`: kerning groups and pair values in units of `p.sb`, so kerning scales with weight.
- `ufo.py`: draws the registry into one ufoLib2 font per master. It sets metrics, names and OS/2, applies the spacing table, and writes kerning.
- `designspace.py`: two axes, six masters, named instances.
- `build.py`: generates UFOs into `sources/generated/` and runs fontmake (`--keep-overlaps`) for the variable TTF, WOFF2, and optional static instances.
- `proof.py`: PNG specimens. The default writes the wght x ROND grid and size waterfall to `proofs/`. `--readme` writes the banner to `docs/images/specimen.png`.

Outside `src/`:

- `scripts/render_glyphs.py`: fast preview of glyphs at every master, rasterised straight from the parametric source with FreeTypePen (needs `freetype-py`).
- `scripts/fetch_reference.sh`: downloads the original font into the gitignored `reference/`.
- `specimen/index.html` and `specimen/specimen.css`: browser test page with wght, ROND, and size sliders. Serve the repo root over HTTP (for example `python -m http.server`) so the WOFF2 loads.
- `.github/workflows/build.yml`: test, build, and proof on push and PR. Pushing a `v*` tag creates a GitHub Release with a zip of the fonts (variable and static) and OFL, via `gh release create`. Third-party actions are not used for releases.

Tests in `tests/`:

| File | Checks |
|---|---|
| `test_geometry.py` | geometry helpers |
| `test_corners.py` | corner rounding math and point counts |
| `test_compat.py` | point structure for every glyph and master, through a point pen |
| `test_charset.py` | exactly full printable ASCII coverage |
| `test_kerning.py` | groups, spacing, and kerning tables |

## Design system (what makes it look like "Computer Font")

- **Left-heavy contrast:**
  - Left and primary verticals use `p.stem`.
  - Right and secondary verticals use `p.stem2`, which is `STEM_CONTRAST` (0.6) x stem.
  - Horizontals use `p.bar`.
  - `frame` and `arch` already apply this contrast.
- **Top-left step:** the signature detail is a small square step (`p.notch`) cut into the outer top-left corner. A matching step often appears on the counter's top-right.
- **Square counters, rectilinear forms.** Diagonals are allowed only as fixed-vertex polygons (`diag`, `vee_points`, parallelograms). K N V X Y Z v use them. The earlier stair-step diagonals were dropped because they read as zig-zags at light weights.
- **Params fields:** `wght`, `rond`, `stem`, `stem2`, `bar`, `notch`, `radius`, `sb`, `dot`, `cap`, `xh`, `asc`, `desc`, `cap_w` (560), `lc_w` (480). `p.adv(box_w)` adds both sidebearings. Every dimension is linear in wght.
- **Components:**
  - Strokes and shapes: `stem`, `bar`, `notched_rect`, `notched_poly(p, pts, tl=..., flip=...)`, `frame`, `arch`, `dot`, `tail_dot`, `desc_hook`, `bowl_counter`, `s_shape`.
  - Diagonals: `diag`, `vee_points`.
  - Widths and positions: `cap_width`, `lc_width`, `mid_bar`, `math_axis`.
  - Dead code: `stair` is unused now and can be removed.

## How compatibility and spacing actually work (gotchas learned)

1. **Six masters, not four:** wght {200, 400, 900} x ROND {0, 100}. fontmake needs a master at the default location. Without a (400, 100) master, ROND would do nothing at Regular.
2. **Point-level compatibility:**
   - `draw_contour` starts at corner 0's end point and closes on corner 0's curve. Do not reorder this.
   - If a path closes on a zero-length line, which happens when rounding consumes a whole edge, point pens drop it in some masters only. That breaks fontmake with "differing number of points".
   - `test_compat.py` checks through `SegmentToPointPen` for exactly this reason.
3. **Overlaps are kept, not merged** (`--keep-overlaps`), because removing overlaps would break compatibility. Overlapping contours don't round their inner joins, so prefer one polygon per connected shape.
4. **Spacing is applied after drawing:**
   - Glyphs draw with their left edge at `x = p.sb`.
   - For glyphs listed in `spacing.py`, `ufo.py` translates the outline so the ink starts at the target lsb. It then sets the advance to ink + lsb + rsb, which ignores the `width=` callback.
   - Unlisted glyphs keep their drawn position and `width=`.
   - To fix spacing, edit `spacing.py` or `kerning.py`, not the glyph functions.
5. **Contour start points:** rotating a contour's start vertex is harmless within a build, as long as all masters match. A dump-diff refactor check should normalise for rotation.

## Known weaknesses (good next tasks)

- `@` and `&` are passable but the weakest glyphs. At Black, `@`'s inner bowl is small.
- N and K are crowded at Black (heavy diagonal). The `stem2` diagonals are very thin at ExtraLight.
- At heavy weights `( )` are only subtly different from `[ ]`.
- `%` rings nearly touch the slash at Black. `~` is a zigzag, not a wave.
- The counters of a, e, and s are tight (about 90 units) at Black.
- `FAMILY_NAME` "Computer Font" is very close to the original's "Computerfont". The owner may rename it before the first release, which is a one-line change in `config.py`.
- Roadmap: Latin-1 (accents via components plus anchors), a width axis, hinting.

## HARD RULES

1. **Identical point structure.** Every glyph must have the same point structure in all 6 masters. No boolean operations. No conditional points that depend on weight or radius.
2. **Shared metrics only.** Define shapes through `Params` and metrics from `config.py`. No magic numbers in glyph files.
3. **DRY.** Any shape used in 3 or more glyphs, or in 2 or more glyph files, goes into `components.py`.
4. **File size.** Keep files under roughly 300–400 lines. Split by responsibility, as `uppercase_diag.py` does.
5. **Never commit the original font.** Never commit `reference/` or anything derived from the original font's files.
6. **No icons or pictograms.** The charset is text glyphs only.
7. **Test and build before committing.** Run `make test` and `make build`. Do not commit while either fails.
8. **Verify visual changes.** After any change to glyph shapes, components, corners, or spacing, render the affected characters with `scripts/render_glyphs.py` (or `make proof` for spacing) and read the PNG before claiming the change works.

## Working with parallel agents

- Give each agent sole ownership of specific glyph files. Shared modules (`config.py`, `geometry.py`, `corners.py`, `components.py`) are edited by one agent at a time, or append-only after re-reading.
- Agents must not run `make build` while others are editing, because `fonts/` and `sources/generated/` are shared. `scripts/render_glyphs.py` is safe to run in parallel.
- The lead commits. Stage explicit paths and **never `git commit -a`**, because that sweeps in other agents' in-progress files.

## Commits

Use conventional commits: `feat:`, `fix:`, `docs:`, `chore:`, `ci:`, `test:`, `refactor:`. Keep the subject short and imperative, with a body explaining why for non-trivial changes.
